# Vibe Coding OS

> 一个让 AI 自动管理软件开发流程的 Vibe Coding 工作系统。
> 你不需要记 PRD、MVP、Architecture、Sprint、Task、QA……这些全部由 AI 管理。你只需要：**说想法 → 关键决策点确认 → 使用并反馈**。

**v3.1 封版**（2026-10-06）· 经 L2 真实项目「求职工作台」6 轮迭代实测验证。

---

## 核心理念

你不是软件项目经理。你不需要学习软件工程流程——AI 负责把复杂流程隐藏起来。

你只需要做三件事：

1. **告诉 AI 你想做什么** ——「我想做一个求职工作台。」
2. **在关键决策点确认** ——「可以。」
3. **使用产品并告诉 AI 哪里需要修改** ——「岗位评分保存以后刷新页面就没了。」

## 仓库结构

| 文件 | 作用 |
|---|---|
| `MASTER.md` | **唯一规则源（Agent 工作手册）**。放进项目根目录，任何 AI 读它即按同一套流程执行：需求→评估→MVP→开发→测试→验收→迭代 |
| `新项目操作指南.md` | 给用户本人看的详细操作说明 |
| `开工操作手册-各Agent通用.md` | 开工速查卡：无论豆包 / ChatGPT / Claude / Cursor / Qoder，流程完全一样 |
| `VibeCodingOS-审阅稿-v3.1-定稿.md` | 封版定稿：六轮审阅账目、缺口清单、迭代协议、遗留风险 |

## 快速开始（4 步）

```
第 0 步  新建项目文件夹，把 MASTER.md 复制进去（只复制这一个文件）
第 1 步  对任意 AI 说：
        「先读取项目文件夹里的 MASTER.md，然后：开始项目。我想做一个【一句话说清产品】。」
第 2 步  等 AI 回四段：① 我理解的项目 ② 等级 L0–L4 + 原因 ③ MVP（必须有/暂不做/成功标准）④ ≤3 个关键问题
第 3 步  回「可以」（= MVP 已确认），之后每轮结束亲自验证 AI 给的「3 个动作」
```

**换 AI / 换设备 / 新开会话**：说「继续这个项目」，AI 读文件夹里的 MASTER + PROJECT_STATE + HANDOFF 自动恢复，不用重新介绍。

## 为什么各 Agent 通用

规则不装在 AI 脑子里，装在**项目文件夹**里：

```
my-project/
├── MASTER.md          ← 唯一规则源（AI 只读）
├── PROJECT.md         ← 项目身份证
├── MVP.md             ← 目标基线
├── PROJECT_STATE.md   ← 项目状态唯一事实来源
├── HANDOFF.md         ← 会话交接（决策/偏好/踩坑）
└── CHANGELOG.md       ← 重要变化
```

哪个 `MASTER.md` 放进去，哪个 AI 就按同一套流程跑——不需要任何 agent 专属配置。

## 核心机制

- **项目等级自动判断**：L0 简单工具 → L4 大型系统，每级有不同的流程深度与 Agent 使用策略
- **先 MVP，小步迭代**：设计 ↓ 开发 ↓ 测试 ↓ 体验 ↓ 反馈 ↓ 下一轮，而非一次设计几个月后才交付
- **禁止过度设计**：不因"看起来专业"自动加微服务 / Kubernetes / Redis / Kafka / Docker / 多 Agent
- **验证证据链**：每轮必须贴命令原文 + 实际输出，用户亲自验收 3 个动作（自动化环境 ≠ 用户环境，实测踩坑）
- **上下文恢复**：换 AI / 新开对话读 5 个文件即恢复，用户无需重新介绍项目

## 实测验证

- **项目**：求职工作台（L2，单文件 HTML + localStorage，无框架无构建）
- **6 轮迭代**：最小闭环（录入→评分→保存→查看）→ 删除 → Bug 修复（原生 confirm 被浏览器静默拦截 → DOM 模态）→ CSV 批量导入 → 导出/导入（跨设备）→ 五态状态机
- **暴露的真问题**：自动化环境 ≠ 用户环境；重绘式 UI 显著增加浏览器自动化成本；localStorage 按设备隔离
